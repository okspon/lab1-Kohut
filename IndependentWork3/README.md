# Звіт з аналізу інкапсуляції в Open-Source проєкті

## 1. Обраний проєкт
- **Назва проєкту:** AutoMapper
- **Опис:** Популярна open-source бібліотека для .NET, яка використовується для автоматичного відображення (mapping) даних з об'єктів одного типу в об'єкти іншого типу.
- **Посилання на GitHub:** [https://github.com/AutoMapper/AutoMapper](https://github.com/AutoMapper/AutoMapper)

## Контрольні запитання

1.За якими ознаками можна зробити висновок, що в класі дотримано інкапсуляції?

Основні ознаки дотримання інкапсуляції — це використання приватних полів для збереження даних, надання доступу до них виключно через публічні властивості або методи, обмеження модифікації даних за допомогою властивостей тільки для читання (read-only) або приватних set-аксесорів, а також повне приховування внутрішньої логіки та обчислень від зовнішнього коду.

2.Які підходи до валідації властивостей ви зустріли в реальному коді?

У реальному коді зустрічаються підходи ранньої валідації (Fail-Fast) у set-аксесорах або конструкторах через перевірку умов та викидання винятків (наприклад, ArgumentNullException чи ArgumentException), використання декларативних атрибутів валідації з System.ComponentModel.DataAnnotations, а також підхід захисного дизайну (Immutability), коли дані перевіряються лише один раз при створенні об'єкта, після чого робляться доступними тільки для читання.

3.Чому для аналізу важливо наводити посилання на конкретні класи та фрагменти коду?

Це підтверджує, що аналіз проведено на основі реального вихідного коду існуючого open-source проєкту, а не вигаданих прикладів. Також це дає можливість викладачу перевірити контекст використаних архітектурних рішень безпосередньо у репозиторії GitHub та наочно проілюструвати конкретні синтаксичні конструкції C#.

4.Які висновки щодо якості проєктування ви зробили після порівняння 2-3 класів?

Аналіз показав, що якісний open-source код віддає перевагу незмінності об'єктів (Immutability) через використання read-only властивостей, що робить програму надійною та безпечною в багатопотоковому середовищі. Окрім цього, строга інкапсуляція зменшує зв'язаність коду між модулями, а перевизначення стандартних методів і операторів порівняння робить роботу з об'єктами зручною та передбачуваною.
