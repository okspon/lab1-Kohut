# Самостійна робота No14

• Тема: Вивчення Dictionary<TKey, TValue> та HashSet<T> у бібліотеках .NET

• Обсяг: 80 хв (2 академічні години)

## Мета

Дослідити реальні приклади використання узагальнених колекцій у популярних .NET-бібліотеках
та зрозуміти, як вони застосовуються для вирішення практичних задач.

1. Які переваги generic-колекцій над неузагальненими структурами даних у .NET?
Узагальнені колекції (List<T>, Dictionary<TKey, TValue>, HashSet<T>) мають три ключові переваги перед неузагальненими (ArrayList, Hashtable):

Безпека типів (Type Safety) на етапі компіляції: Компілятор суворо контролює типи елементів, які додаються до колекції. Це унеможливлює випадкове додавання об'єкта іншого типу та виникнення винятків InvalidCastException під час виконання програми.

Висока продуктивність (відсутність Boxing/Unboxing): Неузагальнені колекції зберігають усі елементи як object. Для значущих типів (int, double, DateTime, struct) це викликає постійне пакування в купу (boxing) при додаванні та розпакування (unboxing) при читанні, що створює навантаження на збирач сміття (GC). Generic-колекції працюють із конкретним типом напряму без витрат пам'яті та процесорного часу.

Чистота коду та повторне використання: Не потрібно писати ручне приведення типів (MyType)collection[i] при кожному зверненні до елемента, а один узагальнений клас підходить для будь-яких типів даних.

2. У яких сценаріях доцільніше використовувати Dictionary<TKey, TValue>, а в яких — HashSet<T>?
Dictionary<TKey, TValue> використовують тоді, коли потрібно встановити відповідність «ключ 
→
→ значення» і швидко отримувати, оновлювати або видаляти асоційовані дані за унікальним ідентифікатором зі складністю 
O(1):

Кешування даних (шлях до файлу 
→
→ метадані, ID користувача 
→
→ профіль).

Індекси та довідники (артикул товару 
→
→ об'єкт товару, код помилки 
→
→ її опис).

Підрахунок частоти елементів (слово 
→
→ кількість входжень у тексті).

HashSet<T> використовують тоді, коли додаткове значення не потрібне, а важливий сам факт присутності унікального елемента або виконання математичних операцій над множинами:

Автоматична фільтрація дублікатів (список унікальних тегів, IP-адрес, email-підписників).

Миттєва перевірка входження за O(1) (перевірка прав доступу, чорні/білі списки, відвідані вузли графа).

Порівняння наборів даних через операції множин: пошук спільних елементів (IntersectWith), об'єднання (UnionWith) або пошук відмінностей (ExceptWith).

3. Як IEqualityComparer<T> впливає на коректність і продуктивність Dictionary та HashSet?
Інтерфейс IEqualityComparer<T> визначає два методи, на яких базується робота хеш-таблиць у .NET: GetHashCode(T obj) та Equals(T x, T y).

Вплив на коректність:

Визначає, за яким саме критерієм два об'єкти вважаються однаковими (наприклад, порівняння рядків без урахування регістру через StringComparer.OrdinalIgnoreCase або порівняння об'єктів Person лише за полем Name, а не за посиланням у пам'яті).

Головне правило коректності: Якщо Equals(x, y) повертає true, то GetHashCode(x) та GetHashCode(y) обов'язково повинні повертати однакове число. Якщо це правило порушити, колекція шукатиме об'єкт не в тому бакеті (комірці) хеш-таблиці й не знайде вже доданий елемент.

Вплив на продуктивність:

Якісна функція GetHashCode рівномірно розподіляє елементи по різних бакетах, забезпечуючи швидкість пошуку, вставки та видалення O(1).

Якщо GetHashCode написаний невдало (наприклад, повертає константу або генерує багато однакових хешів для різних об'єктів), виникають колізії. Усі елементи потрапляють в один ланцюжок, і колекція змушена перебирати їх послідовно через Equals, через що швидкість деградує з 
O(1) до O(n).

4. Чому інвертований індекс зручно будувати саме на базі Dictionary<string, HashSet<int>>?
Така вкладена структура ідеально поєднує переваги обох колекцій для задач повнотекстового пошуку:

Миттєвий пошук слова за
O(1): Зовнішній Dictionary<string, ...> дозволяє за константний час знайти потрібне слово (терм) серед десятків тисяч слів без перебору всіх документів.

Автоматична унікальність ID документів: Внутрішній HashSet<int> гарантує, що якщо слово зустрічається в документі №5 десять разів, ідентифікатор 5 буде збережений у множині лише один раз — дублікати відсікаються автоматично за 
O(1).

Швидкий пошук за кількома словами (AND-запити): Коли користувач шукає документи, де є одночасно слова «C#» і «Dictionary», достатньо взяти два відповідні HashSet<int> і застосувати вбудований метод перетину множин IntersectWith(), який працює значно швидше та простіше, ніж вкладені цикли для списків (List<int>).
