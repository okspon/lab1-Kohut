# Лабораторна робота No10
• Тема: LINQ в дії: фільтри, join, агрегації. Продуктивність.
• Тривалість: 80 хв (2 академічні години)
• Інструмент: .NET SDK, IDE (Visual Studio / VS Code / Rider), Git

## Мета

Навчитися ефективно використовувати LINQ для фільтрації, об’єднання (join) та агрегації даних,
а також аналізувати продуктивність LINQ-запитів.

## Теоретичні відомості

• Фільтрація (Where): Вибирає елементи з колекції, які задовольняють певну умову.
• Проекція (Select): Перетворює елементи колекції на новий тип або форму.
• Об’єднання (Join, GroupJoin): Комбінує елементи з двох колекцій на основі відповідності
ключів.
• Агрегація (Sum, Average, Count, Min, Max, Aggregate): Виконує обчислення над набором
значень і повертає одне значення.
• Відкладене виконання: Запит не виконується, доки не буде здійснено ітерацію по його
результатах.
• Негайне виконання: Запит виконується одразу при виклику методів, таких як ToList(),
ToArray(), Count().

## Контрольні запитання

1. Поясніть різницю між синтаксисом запитів та синтаксисом методів у LINQ. Коли який краще використовувати?
Синтаксис запитів (Query Syntax) — це декларативний синтаксис, схожий на SQL (from ... where ... join ... select). Під час компіляції компілятор C# перетворює його на виклики звичайних методів розширення.

Синтаксис методів (Method Syntax) — це імперативний ланцюжок викликів методів розширення з класу Enumerable із використанням лямбда-виразів (.Where(...).Join(...).Select(...)).

Коли який використовувати:

Синтаксис запитів зручніший та читабельніший при складних з'єднаннях кількох колекцій (join, group join), роботі з кількома джерелами from або використанні проміжних змінних (let).

Синтаксис методів є більш універсальним, оскільки підтримує абсолютно всі оператори LINQ (наприклад, Count(), Sum(), MinBy(), Skip(), Take(), FirstOrDefault(), Distinct(), які не мають ключових слів у Query Syntax).

2. Для чого використовуються операції Join та GroupJoin? У чому їхня відмінність?
Обидві операції об'єднують елементи двох колекцій за спільним ключем (еквівалентний join за рівністю ключів):

Join (аналог INNER JOIN у SQL) повертає плоску послідовність пар лише для тих елементів, які мають збіги в обох колекціях. Якщо для локації немає жодної події, вона не потрапить у результат.

GroupJoin (аналог LEFT OUTER JOIN із групуванням) повертає ієрархічну структуру: кожному елементу першої (зовнішньої) колекції зіставляється колекція всіх відповідних елементів другої (внутрішньої) колекції. Якщо збігів немає, внутрішня колекція буде порожньою, але елемент зовнішньої колекції все одно залишиться в результаті (саме тому в Запиті 3 ми використали GroupJoin, щоб показати 0 подій для порожніх локацій, якщо такі є).

3. Наведіть приклади агрегуючих операцій LINQ та поясніть їхнє призначення.
Агрегуючі операції обробляють послідовність значень і зводять її до одного підсумкового результату (виконуються негайно):

Count() / LongCount() — підраховує кількість елементів у послідовності (або кількість елементів, що задовольняють умову).

Sum() — обчислює суму числових значень у колекції.

Average() — знаходить середнє арифметичне числових елементів.

Min() / Max() — повертають найменше або найбільше значення (а MinBy() / MaxBy() — сам об'єкт із мінімальним/максимальним значенням ключа).

Aggregate() — дозволяє задати власну функцію-акумулятор для нестандартного згортання колекції (наприклад, об'єднання рядків або обчислення добутку всіх елементів).

4. Як можна виміряти продуктивність LINQ-запитів? Які фактори впливають на неї?
Для точного вимірювання часу виконання в .NET використовують клас System.Diagnostics.Stopwatch (а для професійного бенчмаркінгу з виключенням похибок JIT і збирача сміття — бібліотеку BenchmarkDotNet).

Фактори, що впливають на продуктивність LINQ:

Відкладене виконання (Deferred Execution): Сам по собі опис запиту майже не займає часу; реальні витрати відбуваються під час матеріалізації (ToList(), ToArray(), foreach). Повторна ітерація по відкладеному запиту без кешування змушує виконувати всі обчислення заново.

Порядок операцій: Виклик Where() перед Join() або OrderBy() зменшує кількість елементів, які потрібно хешувати чи сортувати.

Алгоритмічна складність та алокації пам'яті: Операції OrderBy, GroupBy, Join, Distinct створюють внутрішні буфери або хеш-таблиці в купі (Heap), що навантажує Garbage Collector (GC), тоді як лінійні операції (Where, Select, First) працюють потоково без зайвих виділень пам'яті.

Холодний старт (JIT-компіляція): Перший виклик LINQ-методів завжди повільніший через компіляцію IL-коду в машинний код.
