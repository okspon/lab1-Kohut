# Лабораторна робота No10
• Тема: LINQ в дії: фільтри, join, агрегації. Продуктивність.
• Тривалість: 80 хв (2 академічні години)
• Інструмент: .NET SDK, IDE (Visual Studio / VS Code / Rider), Git

## Мета
Навчитися ефективно використовувати LINQ для фільтрації, об’єднання (join) та агрегації даних,
а також аналізувати продуктивність LINQ-запитів.
Теоретичні відомості
• Фільтрація (Where): Вибирає елементи з колекції, які задовольняють певну умову.
• Проекція (Select): Перетворює елементи колекції на новий тип або форму.
• Об’єднання (Join, GroupJoin): Комбінує елементи з двох колекцій на основі відповідності
ключів.
• Агрегація (Sum, Average, Count, Min, Max, Aggregate): Виконує обчислення над набором
значень і повертає одне значення.
• Відкладене виконання: Запит не виконується, доки не буде здійснено ітерацію по його
результатах.
• Негайне виконання: Запит виконується одразу при виклику методів, таких як ToList(),
ToArray(), Count().

## Хід роботи
У цій лабораторній роботі я створила консольний проєкт на .NET SDK для моделювання системи управління подіями, де реалізувала класи Event та Venue з колекціями тестових даних із 10–12 елементів. 
Я розробила чотири LINQ-запити для фільтрації подій за роком і місткістю локації, об'єднання даних, підрахунку кількості подій через GroupJoin та пошуку найближчої дати, виконавши кожен із них як у синтаксисі запитів (Query Syntax), 
так і в синтаксисі методів (Method Syntax). За допомогою System.Diagnostics.Stopwatch я виміряла час виконання кожного запиту, проаналізувала їхню продуктивність і зробила висновок, 
що найдорожчими є операції об'єднання з групуванням через витрати на зіставлення ключів, тоді як проста фільтрація та відкладене виконання працюють найшвидше.

## Контрольні питання
1. Поясніть різницю між синтаксисом запитів та синтаксисом методів у LINQ. Коли який краще використовувати?

Синтаксис запитів (Query Syntax): Схожий на мову SQL (from ... in ... where ... select). Він зручніший для читання, коли потрібно створювати складні запити з кількома об'єднаннями (join), групуваннями (group by) або розрахунковими змінними (let).

Синтаксис методів (Method Syntax): Використовує ланцюжки методів розширення (.Where(), .Select(), .OrderBy()) та лямбда-вирази. Він універсальніший, оскільки деякі оператори (наприклад, Take, Skip, Distinct, MinBy, Count) доступні виключно через синтаксис методів.

Коли що використовувати: Query Syntax краще обирати для складних реляційних запитів із багатьма join та group by. Method Syntax краще використовувати для простих фільтрацій, точкових операцій або ланцюжкових перетворень. За продуктивністю вони ідентичні, оскільки компілятор перетворює Query Syntax у виклики методів розширення.

2.Для чого використовуються операції Join та GroupJoin? У чому їхня відмінність?

Join (Inner Join): Об'єднує дві колекції за збігом ключів і повертає плоску послідовність, де кожному елементу з першої колекції відповідає конкретний елемент із другої. Якщо відповідника немає, елемент відсіюється.

GroupJoin (Left Outer Join / Grouping): Пов'язує кожен елемент першої колекції з групою (колекцією) усіх відповідних елементів із другої колекції. Якщо відповідників немає, елемент першої колекції залишається з порожньою групою.

Відмінність: Join повертає структуру «один-до-одного» для кожного збігу, а GroupJoin — ієрархічну структуру «один-до-багатьох».

3. Наведіть приклади агрегуючих операцій LINQ та поясніть їхнє призначення.

Count() / LongCount(): Підраховує кількість елементів у колекції або кількість елементів, що відповідають умові.

Sum(): Обчислює суму числових значень.

Average(): Обчислює середнє арифметичне значення.

Min() / Max(): Знаходить найменше або найбільше значення (або MinBy / MaxBy для пошуку об'єкта за полем).

Aggregate(): Виконує послідовну користувацьку акумуляцію значень (аналог reduce).

4. Як можна виміряти продуктивність LINQ-запитів? Які фактори впливають на неї?

Як виміряти: За допомогою класу System.Diagnostics.Stopwatch, вимірюючи час у тіках (ElapsedTicks) або мілісекундах (ElapsedMilliseconds). Оскільки LINQ використовує відкладене виконання, вимірювати потрібно момент матеріалізації запиту (викликаючи .ToList(), .ToArray(), .Count() або під час проходу циклом foreach). Також перед замірами бажано робити розігрівальний виклик (Warm-up) для виключення часу JIT-компіляції.

Фактори впливу:

Виділення пам'яті: Створення анонімних типів та проміжних списків збільшує навантаження на збирач сміття (Garbage Collector).

Складність алгоритму: Звичайна фільтрація Where має складність 
O(N), а вкладені пошуки чи складні операції без хешування можуть збільшувати складність до 
O(N⋅M).

Тип джерела: LINQ to Objects працює в RAM, тоді як LINQ to Entities (EF Core) транслює запит у SQL, де швидкість залежить від індексів бази даних та мережевих затримок.
