# Звіт з самостійної роботи №8
**Тема:** Вивчення `Dictionary<TKey, TValue>` та `HashSet<T>` у бібліотеках .NET.

---

## Частина 1: Аналіз використання у відкритих проєктах

1. **Приклад `Dictionary<TKey, TValue>` (Низькорівневе кодування JSON у Newtonsoft.Json)**
   - **Контекст:** У бібліотеці Newtonsoft.Json словники використовуються для швидкого пошуку відображень властивостей класу та відповідних назв JSON-ключів.
   - **Чому обрано:** Словник дає змогу за константний час $O(1)$ знаходити відповідне поле об'єкта під час десеріалізації, не перебираючи весь список властивостей.
   - **Складність:** $O(1)$ в середньому для пошуку за ключем.
   - **Особливості:** Часто використовується `StringComparer.Ordinal` для максимізації швидкості порівняння ключів-рядків.

2. **Приклад `HashSet<T>` (Аналіз графу залежностей у AutoMapper)**
   - **Контекст:** При побудові схем відображення типів (Type Maps) AutoMapper відстежує вже оброблені типи для запобігання нескінченній рекурсії у циклічних залежностях.
   - **Чому обрано:** `HashSet<T>` зберігає лише унікальні об'єкти та забезпечує перевірку наявності елемента `Contains` за $O(1)$.
   - **Складність:** $O(1)$ для додавання та перевірки наявності.

3. **Приклад `Dictionary<string, HashSet<int>>` (Кешування та групування в Entity Framework Core)**
   - **Контекст:** EF Core використовує комбінацію словника й множини для групування сутностей за їхніми відстежуваними станами та первинними ключами у `ChangeTracker`.
   - **Чому обрано:** Словник дозволяє швидко отримати групу сутностей за ідентифікатором типу, а `HashSet` миттєво додає та вилучає унікальні екземпляри без дублювання.
   - **Складність:** $O(1)$ для вибірки групи та $O(1)$ для маніпуляцій з унікальними сутностями.

## Частина 3: Порівняльна таблиця

| Операція | List\<T\> | Dictionary\<TKey, TValue\> | HashSet\<T\> | Коли використовувати |
| :--- | :--- | :--- | :--- | :--- |
| **Додавання** | $O(1)$ (в кінець) | $O(1)$ | $O(1)$ | `List` — впорядковане додавання; `HashSet` — захист від дублікатів. |
| **Пошук за значенням** | $O(n)$ | $O(n)$ | $O(1)$ | `HashSet` кращий, якщо потрібна миттєва перевірка наявності елемента. |
| **Пошук за ключем** | N/A | $O(1)$ | N/A | `Dictionary` — при наявності пари «ключ-значення». |
| **Видалення** | $O(n)$ | $O(1)$ | $O(1)$ | `Dictionary`/`HashSet` видаляють за елементом чи ключем без зсуву елементів. |
| **Перевірка наявності** | $O(n)$ | $O(1)$ | $O(1)$ | `HashSet` або `Dictionary.ContainsKey` для частих перевірок під час роботи. |

## Частина 4: Висновки

1. **Коли Dictionary кращий за List:** Коли дані мають природний унікальний ідентифікатор (ключ) і потрібен їхній швидкий вибір без повного перебору колекції.
2. **Коли HashSet є оптимальним вибором:** Коли порядок елементів не має значення, але необхідно гарантувати відсутність дублікатів та виконувати операції множин (об'єднання, перетин, різниця).
3. **Підводні камені:** 
   - Некоректна реалізація `GetHashCode` та `Equals` для кастомних типів призведе до втрати елементів або багів у `HashSet`/`Dictionary`.
   - Зміна стану об'єкта (мутабельного ключа) після додавання в словник змінює його `GetHashCode`, через що об'єкт стане «невидимим» для колекції.
