#Самостійна робота №5
**Тема:** Приклади поліморфізму в .NET.

## 1. Поліморфізм через `System.Object` (`ToString`)
- **Прояв:** Усі класи в .NET успадковуються від `System.Object`, який містить віртуальний метод `ToString()`. Перевизначивши цей метод у власних класах (`Product`, `Customer`, `Order`), ми заносимо їх у єдину колекцію `List<object>`. При виклику `obj.ToString()` C# застосовує пізнє зв'язування та викликає реалізацію відповідного похідного класу.
- **Переваги:** Забезпечує універсальність роботи з об'єктами будь-якого типу та спрощує вивід і логування.

## 2. Поліморфізм через `IEnumerable<T>`
- **Прояв:** Реалізація інтерфейсу `IEnumerable<T>` у класі `MyCustomCollection` дозволяє об'єкту працювати з циклом `foreach`. Зовнішній код не повинен знати про внутрішню структуру збереження даних (наприклад, `List<string>`), оскільки спілкування відбувається через єдиний інтерфейс ератора.
- **Переваги:** Ослаблення зв'язаності коду (Low Coupling) та надання стандартного механізму обходу будь-яких колекцій.

## 3. Поліморфізм через абстрактний клас `Stream`
- **Прояв:** Метод `ProcessStream(Stream stream)` приймає абстрактний клас `Stream`. При передачі об'єктів `FileStream` чи `MemoryStream` виклик `stream.Read(...)` поліморфно виконує специфічне зчитування (з файлу або з оперативної пам'яті).
- **Переваги:** Повторне використання коду та розширюваність — метод `ProcessStream` може обробляти нові типи потоків (наприклад, `NetworkStream`) без змінення власного коду.


## Контрольні запитання

1.Як поліморфізм проявляється при роботі з List<object>?

Поліморфізм проявляється у тому, що колекція List<object> може зберігати посилання на екземпляри будь-яких типів (Product, Customer, Order), оскільки всі класи в C# є похідними від System.Object. Під час обходу списку та виклику методу obj.ToString() C# виконує динамічне (пізнє) зв'язування і викликає саме перевизначену версію ToString(), належну конкретному об'єкту, а не базову реалізацію з System.Object.

2.Що потрібно реалізувати в MyCustomCollection, щоб її можна було перебирати через foreach?

Для цього клас MyCustomCollection повинен реалізувати інтерфейс IEnumerable<T> (або необобщений IEnumerable). Головною вимогою є реалізація методу GetEnumerator(), який повертає об'єкт-ітератор (IEnumerator<T>), що забезпечує послідовний доступ до елементів колекції під час виконання циклу foreach.

3.Чому метод ProcessStream(Stream stream) є прикладом поліморфної роботи з абстрактним класом?

Цей метод є прикладом поліморфізму, оскільки приймає як параметр абстрактний клас Stream, а не його конкретні реалізації. При виклику ProcessStream йому можна передати як FileStream, так і MemoryStream чи NetworkStream. Виклик методів зчитування (наприклад, stream.Read()) всередині ProcessStream виконає відповідну реалізацію для конкретного джерела даних без необхідності змінювати сам код методу.

4.Які переваги дає єдиний інтерфейс роботи для різних типів потоків і колекцій?

Єдиний інтерфейс забезпечує високу гнучкість, повторне використання коду та дотримання принципу відкритісті/закритості (SOLID). Розробник може писати універсальну логіку для обробки даних (наприклад, алгоритми читання з потоків або перебору колекцій), яка працюватиме з будь-якими майбутніми типами джерел чи структур даних без потреби переписувати або duplication коду під кожний окремий клас.
