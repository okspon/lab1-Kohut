# Лабораторна робота No3
• Тема: Життєвий цикл об’єкта та керування ресурсами.
• Інструмент: .NET SDK, IDE (Visual Studio / Rider / VS Code)
## Мета 
Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими
ресурсами, реалізувати інтерфейс IDisposable та патерн Dispose.
# Хід роботи
Під час виконання лабораторної роботи №3 я розробила консольний проєкт на C# з класом CryptoStream, який імітує роботу некерованого ресурсу через прапорець стану потоку та реалізує повний патерн Dispose (включаючи Dispose(), 
захищений Dispose(bool), деструктор ~CryptoStream() і виклик GC.SuppressFinalize). Я практично дослідила три сценарії керування ресурсами: автоматичне звільнення через блок using, явний виклик методу Dispose(), 
а також роботу фіналізатора при примусовому зборі сміття за допомогою GC.Collect(), після чого успішно налаштувала файл .gitignore та відправила чистий код без системних папок до свого GitHub-репозиторію.

## Контрольні запитання
• Що таке життєвий цикл об’єкта в .NET?
Життєвий цикл об’єкта — це процес від його створення до видалення з пам’яті. Спочатку об’єкт створюється за допомогою конструктора, 
потім використовується програмою, а коли він більше не потрібен, збирач сміття (GC) звільняє пам’ять.
• Яка різниця між керованими та некерованими ресурсами?
Керовані ресурси контролюються .NET і автоматично звільняються збирачем сміття. Некеровані ресурси не контролюються .NET повністю, 
тому їх потрібно звільняти вручну. Наприклад, це можуть бути файлові дескриптори або з'єднання з базою даних.
• Для чого призначений інтерфейс IDisposable?
IDisposable використовується для того, щоб клас міг явно звільняти ресурси. Для цього в класі реалізується метод Dispose(), який закриває або звільняє потрібні ресурси.
• Як оператор using допомагає в керуванні ресурсами?
using автоматично викликає Dispose() після завершення роботи з об’єктом. Тому не потрібно окремо писати Dispose(). Це також працює, якщо під час роботи виникне помилка.
• Навіщо в патерні Dispose використовується метод GC.SuppressFinalize()?
GC.SuppressFinalize() повідомляє збирачу сміття, що деструктор для цього об’єкта вже не потрібно викликати. Це потрібно, коли Dispose() вже звільнив ресурси, щоб не виконувати зайву фіналізацію.
• Чому в деструкторі викликається Dispose(false), а в методі Dispose() — Dispose(true)?
Dispose(true) означає, що звільняються керовані ресурси, оскільки метод Dispose() викликається програмою, коли об’єкт ще повністю доступний. Dispose(false) 
викликається деструктором, тому керовані ресурси вже можуть бути недоступні або знищені. У такому випадку звільняються тільки некеровані ресурси.
