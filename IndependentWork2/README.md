# Самостійна робота No2

• Тема: Перевантаження конструкторів: приклади та сценарії.

##Мета

Закріпити навички використання перевантажених конструкторів для створення гнучких та зручних
у використанні класів.

## Хід роботи
У цій роботі я створила проєкт IndependentWork2 та реалізувала клас Product із п'ятьма приватними полями й read-only властивостями. Для забезпечення гнучності створення об'єктів було реалізовано три перевантажені 
конструктори: основний (ініціалізує всі поля), скорочений (встановлює дефолтні значення "Uncategorized" та 0) та конструктор копіювання. Останні два викликають основний конструктор за допомогою синтаксису : this(...), 
що виключає дублювання коду. Також перевизначено метод ToString() для зручного виводу даних про товар, а в Program.cs продемонстровано роботу кожного з конструкторів.

## Контрольні запитання

1.Навіщо потрібне перевантаження конструкторів у класі Product?

Перевантаження конструкторів дозволяє створювати об'єкти товару з різним рівнем деталізації початкових даних. Це робить клас гнучким і зручним для використання: 
товар можна створити як із повним набором характеристик (категорія, складський залишок), так і за наявності лише базових даних (назва та ціна), не змушуючи розробника щоразу вручну передавати відсутні значення.

2.Чому конструктор копіювання зручно реалізовувати через this(...)?

Викликом основного конструктора через : this(...) забезпечується повторне використання вже існуючої логіки ініціалізації полів. Це усуває дублювання коду, 
гарантує однакове присвоєння значень для всіх параметрів та спрощує подальшу підтримку класу (якщо зміниться логіка ініціалізації, її потрібно буде відкоригувати лише в одному місці — в основному конструкторі).

3.Які переваги дає read-only доступ до властивостей після створення об’єкта?

Read-only властивості (з єдиним блоком get або init) гарантують незмінність (immutability) стану об'єкта після його створення. 
Це захищає дані від випадкових або некоректних модифікацій під час виконання програми, підвищує надійність коду, спрощує його відлагодження та забезпечує безпечну роботу в багатопотоковому середовищі.

4.У яких випадках перевизначення ToString() спрощує налагодження та демонстрацію роботи класу?

Перевизначений метод ToString() дозволяє автоматично отримати текстове представлення об'єкта зі структурованими та відформатованими даними замість назви 
його типу (IndependentWork2.Product). Це значно спрощує відлагодження при виводі в консоль через Console.WriteLine(product), логуванні подій у файл чи перегляді вмісту об'єктів у Visual Studio під час виконання програми.
