# Лабораторна робота No5

• Тема: Поліморфізм: динамічне зв’язування та перевизначення методів.

## Мета

Навчитися реалізовувати поліморфну поведінку за допомогою віртуальних методів та їх
перевизначення, а також агрегувати результати поліморфних викликів.
Теоретичні відомості
• Поліморфізм: Здатність об’єктів різних класів реагувати на однаковий виклик методу
по-різному, залежно від їхнього фактичного типу. Досягається за допомогою віртуальних
методів та їх перевизначення.
• Динамічне зв’язування: Визначення того, який метод буде викликаний, відбувається під
час виконання програми, що дозволяє реалізувати поліморфну поведінку.
• virtual: Модифікатор у базовому класі, що дозволяє похідним класам надавати власну
реалізацію методу.
• override: Модифікатор у похідному класі, що вказує на нову реалізацію віртуального
методу базового класу.

## Контрольні запитання

1.Що таке поліморфізм і як він реалізується в C# за допомогою virtual та override?

Поліморфізм — це здатність об'єктів різних класів реагувати на однакові виклики методів по-різному, залежно від їхнього фактичного типу під час виконання програми. У C# він реалізується через віртуальні методи:
Модифікатор virtual додається до методу в базовому класі, що надає дозвіл похідним класам змінювати його поведінку.
Модифікатор override використовується в похідному класі, щоб надати власну нову реалізацію цього віртуального методу.

2.Поясніть поняття динамічного зв’язування. Чим воно відрізняється від статичного?

Динамічне зв'язування (Late Binding): Це процес, за якого вибір конкретного методу для виконання відбувається під час роботи програми (in runtime) на основі реального типу об'єкта в пам'яті. Використовується для віртуальних методів (virtual/override).
Статичне зв'язування (Early Binding): Відбувається на етапі компіляції. Компiлятор одразу знає, який саме код викликати (стосується звичайних невіртуальних методів, перевантажених методів або методів, прихованих через new).

3.Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.

Поліморфізм дозволяє додавати нові типи до системи без зміни існуючої логіки. Наприклад, якщо до нашого проєкту додасться новий тип будівлі Warehouse (Склад), нам достатньо лише створити клас Warehouse : Building та перевизначити GetPurpose(). Код обробки у Main (цикл foreach) залишиться повністю незмінним — він автоматично працюватиме з новим об'єктом без жодного додаткового if чи switch.

Уніфікована обробка: Дозволяє зберігати об'єкти різних похідних класів (House, Office, Shop) у єдиному списку (наприклад, List<Building>).
