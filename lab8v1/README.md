# Лабораторна робота No3
• Тема: Життєвий цикл об’єкта та керування ресурсами.
• Інструмент: .NET SDK, IDE (Visual Studio / Rider / VS Code)
## Мета 
Поглибити розуміння життєвого циклу об’єкта в C#, навчитися працювати з некерованими
ресурсами, реалізувати інтерфейс IDisposable та патерн Dispose.
## Хід роботи
Під час виконання лабораторної роботи №3 я розробила консольний проєкт на C# з класом CryptoStream, який імітує роботу некерованого ресурсу через прапорець стану потоку та реалізує повний патерн Dispose (включаючи Dispose(), 
захищений Dispose(bool), деструктор ~CryptoStream() і виклик GC.SuppressFinalize). Я практично дослідила три сценарії керування ресурсами: автоматичне звільнення через блок using, явний виклик методу Dispose(), 
а також роботу фіналізатора при примусовому зборі сміття за допомогою GC.Collect(), після чого успішно налаштувала файл .gitignore та відправила чистий код без системних папок до свого GitHub-репозиторію.

## Контрольні запитання
1. Що таке життєвий цикл об’єкта в .NET?

Життєвий цикл об’єкта — це процес від його створення до видалення з пам’яті. Спочатку об’єкт створюється за допомогою конструктора, 
потім використовується програмою, а коли він більше не потрібен, збирач сміття (GC) звільняє пам’ять.

2. Яка різниця між керованими та некерованими ресурсами?

Керовані ресурси контролюються .NET і автоматично звільняються збирачем сміття. Некеровані ресурси не контролюються .NET повністю, 
тому їх потрібно звільняти вручну. Наприклад, це можуть бути файлові дескриптори або з'єднання з базою даних.

3. Для чого призначений інтерфейс IDisposable?

IDisposable використовується для того, щоб клас міг явно звільняти ресурси. Для цього в класі реалізується метод Dispose(), який закриває або звільняє потрібні ресурси.

4. Як оператор using допомагає в керуванні ресурсами?

using автоматично викликає Dispose() після завершення роботи з об’єктом. Тому не потрібно окремо писати Dispose(). Це також працює, якщо під час роботи виникне помилка.

5. Навіщо в патерні Dispose використовується метод GC.SuppressFinalize()?

GC.SuppressFinalize() повідомляє збирачу сміття, що деструктор для цього об’єкта вже не потрібно викликати. Це потрібно, коли Dispose() вже звільнив ресурси, щоб не виконувати зайву фіналізацію.

6. Чому в деструкторі викликається Dispose(false), а в методі Dispose() — Dispose(true)?

Dispose(true) означає, що звільняються керовані ресурси, оскільки метод Dispose() викликається програмою, коли об’єкт ще повністю доступний. Dispose(false) 
викликається деструктором, тому керовані ресурси вже можуть бути недоступні або знищені. У такому випадку звільняються тільки некеровані ресурси.

# Лабораторна робота No5
• Тема: Поліморфізм: динамічне зв’язування та перевизначення методів.

• Інструмент: .NET SDK, IDE на вибір студента

## Мета
Навчитися реалізовувати поліморфну поведінку за допомогою віртуальних методів та їх
перевизначення, а також агрегувати результати поліморфних викликів.

## Теоретичні відомості
• Поліморфізм: Здатність об’єктів різних класів реагувати на однаковий виклик методу
по-різному, залежно від їхнього фактичного типу. Досягається за допомогою віртуальних
методів та їх перевизначення.
• Динамічне зв’язування: Визначення того, який метод буде викликаний, відбувається під
час виконання програми, що дозволяє реалізувати поліморфну поведінку.
• virtual: Модифікатор у базовому класі, що дозволяє похідним класам надавати власну
реалізацію методу.
• override: Модифікатор у похідному класі, що вказує на нову реалізацію віртуального
методу базового класу.

## Хід роботи
Я реалізувала лабораторну роботу №5, створивши консольний проєкт на C# (.NET) у власному GitHub-репозиторії. У межах завдання я побудувала ієрархію класів Building $\rightarrow$ House, Office, Shop, 
застосувала поліморфізм за допомогою віртуального методу GetPurpose() та модифікаторів virtual/override,
продемонструвала динамічне зв'язування через колекцію базового типу List<Building> і виконала агрегацію результатів поліморфних викликів у підсумковий список. 

## Контрольні запитання
1.Що таке поліморфізм і як він реалізується в C# за допомогою virtual та override?

Поліморфізм -це здатність об'єктів різних класів реагувати на однакові виклики методів по-різному, залежно від їхнього фактичного типу під час виконання програми. У C# він реалізується через віртуальні методи:

Модифікатор virtual додається до методу в базовому класі, що надає дозвіл похідним класам змінювати його поведінку.

Модифікатор override використовується в похідному класі, щоб надати власну нову реалізацію цього віртуального методу.

2.Поясніть поняття динамічного зв’язування. Чим воно відрізняється від статичного?

Динамічне зв'язування (Late Binding): Це процес, за якого вибір конкретного методу для виконання відбувається під час роботи програми (in runtime) на основі реального типу об'єкта в пам'яті. 
Використовується для віртуальних методів (virtual/override).

Статичне зв'язування (Early Binding): Відбувається на етапі компіляції. Компiлятор одразу знає, який саме код викликати (стосується звичайних невіртуальних методів, перевантажених методів або методів, прихованих через new).

3.Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.

Поліморфізм дозволяє додавати нові типи до системи без зміни існуючої логіки. Наприклад, якщо до нашого проєкту додасться новий тип будівлі Warehouse (Склад), нам достатньо лише створити клас Warehouse : 
Building та перевизначити GetPurpose(). Код обробки у Main (цикл foreach) залишиться повністю незмінним — він автоматично працюватиме з новим об'єктом без жодного додаткового if чи switch.

4.Які переваги дає використання колекцій базових типів для роботи з поліморфними об’єктами?

Уніфікована обробка: Дозволяє зберігати об'єкти різних похідних класів (House, Office, Shop) у єдиному списку (наприклад, List<Building>).

Спрощення коду: Зникає потреба створювати окремі масиви чи списки під кожен тип і писати для них дубльовані цикли.
