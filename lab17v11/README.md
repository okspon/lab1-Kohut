##Мета

Навчитися використовувати оператор SelectMany для роботи з вкладеними колекціями,
реалізовувати пагінацію даних за допомогою LINQ, а також створювати власні методи
розширення для IEnumerable<T> або ключових доменних сутностей.

## Хід роботи

У ході виконання лабораторної роботи я створила консольний проєкт мовою C# та реалізувала об'єктну модель предметної області з ієрархією вкладених колекцій (Event $\rightarrow$ Participant $\rightarrow$ Ticket), заповнивши її тестовими даними. За допомогою LINQ-оператора SelectMany я виконала «розгортання» багаторівневих списків для отримання єдиної плоскої колекції всіх квитків, а за допомогою методів Skip і Take організувала посторінкову пагінацію подій. Крім того, я розробила власний метод розширення TotalTicketRevenue() для IEnumerable<Event> для підрахунку загального доходу від продажу квитків та продемонструвала роботу всіх запитів у консолі.

## Контрольні питання
1. Для чого використовується оператор SelectMany? Наведіть приклад, що демонструє його відмінність від Select.

Оператор SelectMany використовується для проєкції кожного елемента вихідної колекції у вкладену колекцію та подальшого «вирівнювання» (flattening) усіх цих вкладених колекцій в одну єдину плоску послідовність.

Select повертає колекцію колекцій (зберігає вкладену структуру, співвідношення «1 до 1» для зовнішніх елементів).

SelectMany об'єднує всі елементи внутрішніх колекцій в один лінійний список.

Приклад:

C#
// Є список учасників, у кожного — List<Ticket> Tickets
// Select поверне IEnumerable<List<Ticket>> (список списків квитків):
IEnumerable<List<Ticket>> nested = participants.Select(p => p.Tickets);

// SelectMany поверне IEnumerable<Ticket> (один плоский список усіх квитків):
IEnumerable<Ticket> flat = participants.SelectMany(p => p.Tickets);

2. Як реалізувати пагінацію даних за допомогою LINQ? Які методи для цього використовуються?

Для реалізації пагінації (посторінкового розбиття даних) у LINQ використовуються два методи розбиття (partitioning operators):

Skip(int count) — пропускає задану кількість елементів від початку послідовності.

Take(int count) — бере задану кількість елементів після пропущених.

Стандартна формула для отримання сторінки з номером pageNumber (нумерація з 1) та розміром pageSize:

C#
var page = collection
    .Skip((pageNumber - 1) * pageSize)
    .Take(pageSize);
(Примітка: перед викликом Skip/Take бажано впорядкувати колекцію через OrderBy, щоб порядок елементів на сторінках був детермінованим).

3. Поясніть концепцію методів розширення. Як вони інтегруються з LINQ?

Методи розширення (Extension Methods) дозволяють «додавати» нові методи до вже існуючих класів, структур або інтерфейсів без зміни їхнього вихідного коду, перекомпіляції чи створення похідних класів.

Правила оголошення:

Метод має бути оголошений у не-узагальненому статичному класі (static class).

Сам метод має бути статичним (static).

Перший параметр методу визначає тип, який розширюється, і має містити модифікатор this.

Інтеграція з LINQ:
Увесь стандартний LINQ to Objects побудований саме на методах розширення для інтерфейсу IEnumerable<T> (у класі System.Linq.Enumerable). Завдяки цьому будь-яка колекція (List<T>, масив, HashSet<T> тощо) автоматично отримує доступ до методів Where, Select, SelectMany, Skip, Take, а власні методи розширення для IEnumerable<T> безшовно вбудовуються в ланцюжки LINQ-запитів (method chaining).

4. Наведіть приклад власного методу розширення для IEnumerable<T> та поясніть його призначення.

Окрім методу TotalTicketRevenue() з варіанта, можна створити узагальнений метод пагінації для будь-якої колекції IEnumerable<T>:

C#
public static class EnumerableExtensions
{
    public static IEnumerable<T> Paginate<T>(this IEnumerable<T> source, int pageNumber, int pageSize)
    {
        if (source == null) throw new ArgumentNullException(nameof(source));
        if (pageNumber < 1) pageNumber = 1;
        if (pageSize < 1) pageSize = 10;

        return source.Skip((pageNumber - 1) * pageSize).Take(pageSize);
    }
}
Призначення: Метод Paginate<T> інкапсулює логіку розрахунку зміщення (pageNumber - 1) * pageSize та перевірку коректності параметрів сторінки. Це позбавляє від дублювання коду в різних частинах програми та дозволяє викликати пагінацію лаконічно в будь-якому LINQ-ланцюжку: events.Paginate(1, 2).
