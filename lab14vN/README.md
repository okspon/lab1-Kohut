# Лабораторна робота No8
• Тема: Делегати й лямбда-вирази у практиці колекцій: CollectionHelper<T>.

• Інструмент: .NET SDK, IDE (Visual Studio / VS Code)

## Мета
Навчитися передавати поведінку як параметр через делегати Func, Action, Predicate, будувати
на цій основі універсальні операції над колекціями та використовувати лямбда-вирази у практиці
ООП.

## Теоретичні відомості
• Делегат: Тип, що представляє посилання на метод з певною сигнатурою.
• Анонімний метод: Метод без імені, який можна присвоїти делегату.
• Лямбда-вираз: Компактний синтаксис для написання анонімних функцій.
• Func<T, TResult>: Узагальнений делегат для методів, що приймають параметри та
повертають значення.
• Action<T>: Узагальнений делегат для методів, що приймають параметри, але не
повертають значення (void).
• Узагальнений метод: Метод, який може працювати з різними типами даних, що вказуються
при його виклику.

## Хід роботи
У цій лабораторній роботі я створила консольний застосунок на мові C# для практики роботи з делегатами та лямбда-виразами. Я реалізувала статичний узагальнений клас CollectionHelper<T> та власний узагальнений метод Count, 
який приймає колекцію IEnumerable<T> і делегат Predicate<T> для підрахунку елементів, що відповідають заданій умові. Щоб продемонструвати власний алгоритм обходу колекції, я виконала завдання через цикл foreach без використання готового
LINQ-оператора Count(). У методі Main я перевірила роботу утиліти на трьох різних типах даних: шукала від'ємні числа в List<int>, відбирала слова за довжиною в List<string> та фільтрувала товари за ціною і наявністю в кастомному класі Product, 
передаючи умови через лямбда-вирази, після чого розв'язала конфлікти версій та запушила готовий проєкт у свій GitHub-репозиторій.

## Контрольні запитання

1. Що таке делегат і для чого він використовується?

Делегат - це тип, який представляє безпечний до типів покажчик (посилання) на метод із певним списком параметрів та типом повернення. Він використовується для того, щоб передавати методи як параметри в інші методи, зберігати їх у змінних та викликати динамічно або послідовно (у випадку багатоадресних делегатів).

2. У чому полягає різниця між Func та Action?

Action<T> представляє метод, який приймає параметри (до 16 елементів), але не повертає значення (має тип повернення void).

Func<T, TResult> представляє метод, який приймає параметри (до 16 елементів) та обов'язково повертає значення типу TResult (останній тип-параметр завжди визначає тип повертаного значення).

3. Як лямбда-вирази спрощують роботу з делегатами?

Лямбда-вирази дають компактний синтаксис для створення анонімних функцій через оператор => безпосередньо у місці виклику. Вони усувають потребу оголошувати окремі класичні методи чи громіздкі анонімні методи з ключовим словом delegate, роблячи код значно коротшим, чистішим і виразнішим.

4. Які переваги дають узагальнені методи при роботі з колекціями?

Універсальність та повторне використання (Reusability): Узагальнений метод створюється один раз і може працювати з колекціями будь-яких типів даних.

Строга типізація та безпека: Перевірка типів виконується на етапі компіляції, що запобігає помилкам під час виконання програми.

Продуктивність: При роботі зі значущими типами (наприклад, int, double) відсутні витрати ресурсів на упаковку/розпаковку (boxing/unboxing), на відміну від роботи з не-узагальненим типом object.

## Реалізований метод
Реалізовано статичний узагальнений метод:
`public static int Count<T>(IEnumerable<T> collection, Predicate<T> predicate)`

Метод повертає кількість елементів у колекції, що задовольняють умову `predicate`. Реалізовано через власний цикл `foreach` без використання готового LINQ-оператора `Enumerable.Count()`.
