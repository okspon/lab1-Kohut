# Лабораторна робота No7
• Тема: Узагальнені типи (Generics). IRepository з where-обмеженнями та тестами.

• Інструмент: .NET SDK, IDE (Visual Studio / VS Code), xUnit

## Мета

Навчитися створювати узагальнені інтерфейси та класи, застосовувати where-обмеження
для типів-параметрів, а також розробляти юніт-тести для перевірки коректності узагальнених
реалізацій.

## Теоретичні відомості

• Generics: Дозволяють створювати класи, інтерфейси та методи, які можуть працювати з
даними будь-якого типу, забезпечуючи безпеку типів та продуктивність.

• where обмеження: Використовуються для накладання обмежень на типи, які можуть бути
використані як аргументи типу для узагальнених класів/методів (наприклад, where T :
class, where T : new(), where T : IInterface).

• IRepository: Поширений шаблон проектування для абстрагування логіки доступу до даних.
Узагальнений IRepository<T> дозволяє працювати з будь-яким типом сутності T.

• Юніт-тести: Автоматизовані тести, що перевіряють окремі, ізольовані одиниці коду (методи,
класи) на коректність їх роботи.

## Хід роботи

У цій лабораторній роботі я створила консольний проєкт lab12v11 та тестовий проєкт lab12v11.Tests на базі .NET 10 і xUnit. Для Варіанту 11 я реалізувала інтерфейс IEntity та сутність Movie з властивостями Id, Title, 
Director і ReleaseYear, узагальнений інтерфейс IRepository<T> з where-обмеженнями (where T : class, IEntity) та його реалізацію InMemoryRepository<T> для виконання CRUD-операцій у пам'яті. Для перевірки роботи репозиторію я написала 10 юніт-тестів, 
які покривають додавання, отримання, оновлення, видалення елементів та обробку винятків (усі тести пройшли успішно), а також налаштувала .gitignore та вивантажила проєкт у GitHub-репозиторій.

## Контрольні запитання

1. Яка роль where-обмежень у Generics? Наведіть приклади їх використання.

Роль: where-обмеження (constraints) задають чіткі вимоги до типів-параметрів T. Без обмежень компілятор вважає, що T може бути чим завгодно, тому дозволяє викликати лише базові методи object. Обмеження гарантують, що тип має необхідні властивості, методи або конструктори, забезпечуючи безпеку типів на етапі компіляції.

Приклади:

where T : class — тип має бути посилальним (reference type).

where T : struct — тип має бути значущим (value type).

where T : new() — тип повинен мати публічний конструктор без параметрів.

where T : IEntity — тип повинен реалізовувати інтерфейс IEntity (як у цій лабораторній роботі).

2. Навіщо потрібен шаблон IRepository? Які переваги він дає?

Призначення: Шаблон Repository відокремлює логіку доступу до даних (база даних, оперативна пам'ять, файл, API) від бізнес-логіки додатка.

Переваги:

Абстрагування: Коду вищого рівня не важливо, де й як саме зберігаються об'єкти.

Тестованість: Дозволяє легко замінити реальну базу даних на заглушку в пам'яті (InMemoryRepository) під час написання юніт-тестів.

Відсутність дублювання: Узагальнений IRepository реалізує універсальний базовий набір CRUD-операцій для будь-якої сутності.

3. Поясніть, чому юніт-тести є важливими при розробці узагальнених компонентів.

Узагальнені компоненти створюються для повторного використання з різними типами даних. Юніт-тести дозволяють переконатися, що алгоритм працює стабільно та однаково коректно для будь-якого типу T, який відповідає обмеженню where. Вони гарантують правильну обробку крайових випадків (null-значення, відсутні ID, виняткові ситуації) без необхідності ручного тестування кожного типу сутності.

4. Які проблеми вирішують Generics порівняно з використанням object?

Строга типізація (Type Safety): Помилки невідповідності типів виявляються ще під час компіляції, а не в процесі виконання програми (Runtime).

Продуктивність: Відсутність операцій упаковки та розпаковки (boxing/unboxing) для значущих типів (Value Types), що економить пам'ять та ресурси процесора.

Чистота та читабельність коду: Зникає потреба в постійному явному приведенні типів (наприклад, (Movie)item).
