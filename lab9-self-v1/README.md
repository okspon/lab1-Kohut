# Звіт з самостійної роботи №9
**Тема:** Делегати й лямбда-вирази: власні утиліти для колекцій.

## 1. Завдання та реалізація
В рамках роботи було створено статичний узагальнений клас `CollectionUtils`, який містить чотири методи-утиліти для маніпуляції колекціями за допомогою делегатів:
- `Map<TSource, TResult>` — приймає `Func<TSource, TResult>` для трансформації кожного елемента.
- `MaxBy<T, TKey>` — приймає `Func<T, TKey>` для пошуку елемента з максимальним значенням ключа.
- `Filter<T>` — приймає `Predicate<T>` для відбору елементів за умовою.
- `ForEach<T>` — приймає `Action<T>` для виконання дії над кожним елементом.

---

## 2. Відповіді на питання звіту

### Навіщо потрібні делегати для створення таких утиліт?
Делегати дозволяють відокремити алгоритм обходу колекції від конкретної логіки обробки даних. Вони передають поведінку (функцію/метод) як параметр у метод, роблячи утиліти повністю універсальними та придатними для повторного використання з будь-якими типами даних та умовами.

### Як лямбда-вирази спрощують виклик цих методів?
Лямбда-вирази (`p => p.Price > 1000`) дозволяють записувати анонімну функцію безпосередньо у місці виклику методу, уникаючи необхідності оголошувати окремі іменовані класи чи методи. Це робить код значно коротшим, виразнішим та легшим для читання.

### Порівняння власних методів із вбудованими LINQ-операторами
- `Map` є аналогом LINQ-оператора `Select`.
- `Filter` є аналогом LINQ-оператора `Where`.
- `MaxBy` відповідає LINQ-методу `MaxBy` (включеному в .NET 6+).
- `ForEach` аналогічний методу `List<T>.ForEach`.

*Основна відмінність:* Наші власні методи виконуються негайно (Eager Evaluation) і повертають нові списки `List<T>`, тоді як більшість операторів LINQ використовують відкладене виконання (Deferred Execution) через `yield return`.
